# Proof points

Convert real work into claims with evidence. Do not summarize a project; package the proof that something changed because the work happened.

Load `references/proof-block-format.md` before writing.

## Core rule

Every proof point shows the full chain: source evidence, before, intervention, after, value, reusable claim. If a claim lacks evidence, label it a hypothesis or draft. Never invent a metric.

## Workflow

1. **Locate evidence.** Read what the user provided: notes, outputs, decisions, reports, dashboards, messages. Ask for a source when a claim has none.
2. **Extract the change.** What was true before, what was built or changed, what is true now.
3. **Name the value.** Speed, quality, clarity, risk reduction, revenue, reuse. Pick the one or two that are real.
4. **Package by audience.** Resume, portfolio, post, sales page, internal. Use the variants in the reference.
5. **Write the proof note** in the format from the reference. Name the file with `scripts/slugify.py "<title>"`.
6. **Say where it goes next.**

## Package when at least one is true

- It shows a system, automation, or workflow that now exists and did not before.
- It can become a case study or a resume bullet with numbers.
- It supports an offer or a position the user is building.
- It documents a shipped capability.

## Do not package when

- The work is only an idea.
- The claim would need a fabricated number.
- The source is too sensitive to summarize safely.
- The result is ordinary note organization, not a change in outcomes.

## Voice

Proof notes are read by people. Apply the edit sub-skill's principles to the reusable claims: concrete nouns, numbers with sources, verbs that do the work, no puffery.
