# Intake

Decide the route from the request, then follow that sub-skill's `SKILL.md`.

## Routing

- The user shares a draft and wants it better, fixed, tightened, cleaned, or "less AI": **edit**.
- The user asks whether a draft is AI, reads as AI, or wants it audited, scanned, flagged, or checked without changes: **detect**.
- The user shares notes, a project summary, a report, or a changelog and wants bullets, a case study, outcomes, or claims: **proof-points**.
- The user asks for two of these, run them in order: detect, then edit; or proof-points, then edit.

## The one question

Ask only if the answer changes the work:

- No draft or notes provided: ask for them.
- Audience or destination unclear for an edit: "Who is this for and where will it be published?"
- Goal unclear: "What should the reader think, feel, or do after reading it?"

Do not ask more than one question before starting. If the user already answered it in the request, do not ask.

## Hand-off

State the route in one line ("Editing for a LinkedIn post, keeping your voice"), then do the work. Do not explain the routing logic.
